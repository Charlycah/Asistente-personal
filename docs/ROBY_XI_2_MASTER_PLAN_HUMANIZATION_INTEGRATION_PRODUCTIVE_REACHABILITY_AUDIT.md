## 1. Baseline and purpose

This audit follows the Owner-certified documentary-precedence baseline:

`13,325 PASS / 0 FAIL / Ruff clean`

Its purpose is to distinguish a capability that exists from a capability that
materially affects ROBY's ordinary productive interaction.

The audit therefore uses four reachability classes:

- `REACHABLE`: a productive path and consumer are demonstrated.
- `PARTIAL`: productive pieces exist, but ordinary-turn integration is bounded.
- `DORMANT`: substantial certified implementation exists without a demonstrated
  ordinary productive consumer path in the current composition.
- `DUPLICATE-RISK`: a new owner would duplicate an existing authority.

No desired fictional behavior model is itself an implementation authority.

## 2. Governing architectural distinction

Humanization is not one capability.

It is the governed composition of existing owners for identity, Memory,
relationship evidence, presence, personality, Conversation, Relevance, Curiosity,
Initiative, reflection, expression and voice.

The required design principle is:

`HUMANIZATION = COMPOSITION OF EXISTING AUTHORITIES`

not:

`HUMANIZATION = NEW HUMANIZATION BRAIN`

## 3. Ordinary productive conversation

The official runtime builds and registers current conversation infrastructure,
including:

- `presence.continuity`;
- `conversation.living_runtime`;
- multimodal conversation integration;
- conversation intelligence;
- the official governed conversation pipeline;
- the unified capability registry.

The official conversation gateway is a real productive consumer for governed
Curiosity when explicit curiosity/relevance inputs are supplied.

It also observes relational-affective evidence from runtime relationship and
adaptive-personality projections when those projections are available.

This proves productive seams exist, but it does not prove that every humanization
authority is continuously active on an ordinary turn.

into the system prompt.

However, repository-wide productive-source inspection found `CognitivePipeline`
construction in tests, not in the current `app/` composition root.

Classification:

`STABLE_PERSONALITY_RICH_PIPELINE: DORMANT_FOR_CURRENT_ORDINARY_RUNTIME`

`RELATIONSHIP_MEMORY_RICH_PIPELINE: DORMANT_FOR_CURRENT_ORDINARY_RUNTIME`

ordinary productive conversation consumes those signals.

A future residual must reuse these owners rather than recreate them.

`PRESENCE_RUNTIME: REACHABLE / BOUNDED`

`LIVING_CONVERSATION: REACHABLE_ON_EXPLICIT_PATH / PARTIAL_FOR_ORDINARY_TURNS`

but no new Living Conversation authority is justified.

existing voice reader when a runtime profile is available.

Repository-wide productive inspection found consumers of
`adaptive_personality_profile` in the Desktop and conversation evidence path, but
did not find a current productive producer/property for that profile in the
official runtime composition.

Classification:

`ADAPTIVE_PERSONALITY_AUTHORITY: EXISTING`

`ADAPTIVE_DELIVERY_TONE_DESKTOP_SEAM: REACHABLE_IF_PROFILE_AVAILABLE`

`ADAPTIVE_PERSONALITY_PROFILE_CURRENT_RUNTIME_PRODUCTION: UNPROVEN / DORMANT`

`VOICE_IDENTITY: FUTURE / DISTINCT`

The smallest possible future residual is therefore not a new personality system.
It is proof or restoration of the canonical profile-production and projection
path, if the next contractual reconciliation confirms that gap.
