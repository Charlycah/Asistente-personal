# ROBY XI.2 — R-CI-SI-S5-B2-A3-A
## Explicit Comparative Discrimination Effect Origin / Authorization — Contract RED

Status: RED CONTRACTUAL — pending OWNER CERTIFICATION

## 1. Purpose

Freeze the minimum governed contract for admitting an explicit comparative
discrimination effect over the exact resolution-path pair already anchored by
an admitted requirement satisfaction.

This block establishes only that an explicit governed declaration attributes
an explicit effect to each exact path A and B for the exact satisfied
requirement/evidence lineage.

It does not infer the effect from evidence content, certify universal truth,
prefer or rank a path, select a path, or authorize acquisition or execution.

## 2. Certified input boundary

The immediate epistemic upstream authority is R-CI-SI-S5-B2-A2-B.

The admission boundary MUST consume an actual `ExplicitRequirementSatisfaction`
artifact S. It MUST NOT reconstruct satisfaction from detached materialization,
requirement, evidence, path, identity, or lineage artifacts.

The certified chain is:

`ExplicitRequirementSatisfaction S`
+ explicit comparative-discrimination-effect declaration
→ admitted explicit comparative discrimination effect
→ STOP.

S already preserves the actual materialization M, requirement R, canonical
EvidenceReference E, epistemic need X, and exact path pair A/B through R. This
foundation MUST reuse those anchors exactly.

## 3. Existing authority boundaries

The following existing authorities MUST remain unchanged:

- S5-B2-A1 owns the exact path-discrimination requirement R and path pair A/B;
- S5-B2-A2-A owns explicit materialization and binding of E to R;
- S5-B2-A2-B owns positive explicit requirement satisfaction;
- `EvidenceReference` owns canonical evidence-reference identity;
- hypothesis discrimination remains hypothesis-specific;
- claim-evidence roles remain claim-specific;
- counterfactual path comparison remains counterfactual-domain-specific;
- conversational source selection remains information-source-specific;
- preference, ranking, selection, and authorization remain downstream.

A satisfied requirement does not establish its comparative effect.

`SATISFIES(R,E) ≠ COMPARATIVE_EFFECT(E,A,B)`.

A hypothesis relation or claim-evidence role MUST NOT be transplanted onto
resolution paths merely to manufacture comparative semantics.

## 4. Required explicit declaration

The declaration MUST be explicit and MUST identify at minimum:

- the exact requirement identity already preserved by S;
- the exact canonical evidence identity already preserved by S;
- the exact identity of path A already anchored by S.requirement;
- the exact identity of path B already anchored by S.requirement;
- one explicit non-blank effect value relative to path A;
- one explicit non-blank effect value relative to path B;
- the declaration provenance authority;
- non-empty evidence codes supporting the declaration lineage.

Path identity is the exact structural pair:

`(capability_name, declared_evidence_output)`.

The authorized provenance for this foundation is exactly:

`governed_explicit_comparative_discrimination_effect_declaration`

The effect values are explicit opaque governed values. This contract does not
create a closed effect enum, map effect values to preference, or interpret
them as truth, ranking, selection, or authorization.

The declaration MUST NOT infer effect from:

- requirement text, labels, names, or free-text descriptions;
- evidence summary, content, metadata, or optional fields;
- source type, source id, fingerprint, or evidence identity alone;
- evidence codes from any upstream or current declaration;
- provenance alone;
- confidence, quality, freshness, timestamps, or source authority;
- capability metadata, semantic terms, tags, or declared topics;
- registry availability or runtime readiness;
- human, creator, household, document, or source identity;
- fuzzy matching, semantic matching, embeddings, LLMs, or retrieval;
- argument order or path ordering as a hidden winner/loser signal.

`SOURCE OF E ≠ PATH FAVORED BY E`.

`ORIENTATION ≠ PREFERENCE`.

## 5. Admission authority

A future narrow admission boundary MAY admit the declaration only when all
contractual conditions are satisfied.

The admission authority MUST:

- consume the actual S artifact;
- consume the explicit declaration;
- preserve S, M, R, E, X, and the exact A/B anchors;
- require exact declaration correspondence to S.requirement_identity;
- require exact declaration correspondence to S.evidence_id;
- require exact declaration correspondence to path A identity from R;
- require exact declaration correspondence to path B identity from R;
- require non-blank explicit effect values for both A and B;
- require exact authorized provenance;
- require non-empty explicit declaration lineage;
- fail closed on any mismatch;
- remain read-only, derivational, and inert.

It MUST NOT query a capability registry, evidence registry, or runtime to
reconstruct or revalidate upstream anchors.

It MUST NOT inspect evidence content to decide the effect.

It MUST NOT reinterpret the explicit effect values.

`DECLARER ≠ ADMISSION AUTHORITY`.

`ADMISSION AUTHORITY ≠ COGNITIVE AUTHORITY`.

`ADMISSION AUTHORITY ≠ TRUTH AUTHORITY`.

## 6. Admitted relation

A positive admitted artifact MUST preserve at minimum:

- the actual `ExplicitRequirementSatisfaction` S;
- the actual materialization M preserved by S;
- the actual requirement R preserved by S;
- the actual canonical evidence E preserved by S;
- X identity, source reference, and lineage kind preserved by S;
- the exact requirement identity;
- the exact evidence identity and canonical evidence provenance fields;
- the exact path A eligibility anchor inherited from R;
- the exact path B eligibility anchor inherited from R;
- the explicit effect value relative to A;
- the explicit effect value relative to B;
- the comparative-effect declaration provenance;
- the comparative-effect declaration evidence codes;
- read-only and derivational semantics.

The admitted artifact MUST NOT mutate or reconstruct upstream artifacts.

The effect values remain explicit declared semantics. Admission does not
convert them into a preference, score, rank, winner, loser, or truth claim.

## 7. Rejection and absence semantics

Absence or rejection of a comparative-effect declaration is epistemically
neutral.

The following implications are forbidden:

`NO EFFECT ADMISSION → NO EFFECT`.

`NO EFFECT ADMISSION → NEUTRAL EFFECT`.

`NO EFFECT ADMISSION → INDISTINGUISHABLE`.

`NO EFFECT ADMISSION → A == B`.

`NO EFFECT ADMISSION → E DOES NOT DISCRIMINATE`.

A mismatch, missing declaration, blank effect value, blank lineage, inferred
origin, or unauthorized provenance MUST fail closed without manufacturing a
negative comparative conclusion.

## 8. Cardinality and conflict boundary

This foundation MUST NOT impose a global one-effect-per-satisfaction rule.
Multiple independently admitted explicit effect declarations MAY exist for the
same upstream satisfaction when separately and validly declared.

This foundation MUST NOT:

- aggregate effects;
- reconcile conflicting effects;
- replace prior effects;
- choose a dominant effect;
- calculate consensus;
- rank declarations;
- rank paths;
- derive preference from cardinality.

Any future conflict reconciliation is a separate capability and is not
authorized here.

## 9. Contract requirements R1-R8

### R1 — Exact existing satisfaction anchor is mandatory

Admission MUST consume an actual `ExplicitRequirementSatisfaction` S.
Detached M/R/E artifacts, raw ids, copied lineage, or reconstructed satisfaction
MUST NOT substitute for S. No A1, A2-A, or A2-B semantics may be recreated.

### R2 — Exact requirement/evidence correspondence

The declaration requirement identity MUST exactly equal
`S.requirement_identity`, and the declaration evidence identity MUST exactly
equal `S.evidence_id`.

Any mismatch MUST fail closed. No inference, repair, normalization, fuzzy
matching, semantic matching, LLM, or retrieval is allowed.

### R3 — Exact inherited A/B path correspondence

The declaration MUST identify path A and path B by the exact structural
`(capability_name, declared_evidence_output)` identities already preserved by
`S.requirement.path_a_eligibility` and `S.requirement.path_b_eligibility`.

A/B MUST NOT be reconstructed from registries, runtime state, source metadata,
text, or semantic terms. Path order MUST NOT silently encode preference.

### R4 — Explicit opaque effect semantics

The declaration MUST provide one non-blank explicit effect value relative to A
and one non-blank explicit effect value relative to B.

Admission MUST preserve these values exactly and MUST NOT infer, normalize,
score, compare, translate, reinterpret, or map them to a closed enum.

This contract does not authorize `FAVORS_A`, `FAVORS_B`, `NEUTRAL`,
`INCONCLUSIVE`, `SUPPORTS`, `CONTRADICTS`, or any other universal taxonomy.

### R5 — Dedicated provenance and explicit lineage

The declaration provenance MUST equal exactly:

`governed_explicit_comparative_discrimination_effect_declaration`

Declaration evidence codes MUST be non-empty and non-blank. They establish
only declaration lineage; they MUST NOT establish effect correctness, truth,
preference, or selection.

Upstream requirement, materialization, or satisfaction provenance MUST NOT
substitute for this provenance. Human, creator, or household identity grants
no bypass.

### R6 — Exact upstream preservation

A positive admission MUST preserve the actual S, M, R, E, X, A, B, requirement
identity, evidence identity, and upstream lineage without mutation or
reconstruction.

The admission MUST NOT query capability, evidence, or runtime registries and
MUST NOT require E to originate from A or B.

`SOURCE OF E ≠ PATH FAVORED BY E`.

### R7 — Absence/rejection is neutral and admitted effect is not truth

No admission or rejected admission MUST NOT imply neutral effect,
indistinguishability, equality, no discrimination, or a negative comparative
result.

A positive admitted effect MUST NOT certify universal truth and MUST NOT imply
preference, ranking, selection, authorization, or path invalidity.

`ADMITTED EFFECT ≠ TRUTH`.

`COMPARATIVE EFFECT ≠ PREFERENCE`.

`COMPARATIVE EFFECT ≠ RANKING`.

`COMPARATIVE EFFECT ≠ SELECTION`.

`COMPARATIVE EFFECT ≠ AUTHORIZATION`.

### R8 — Read-only, derivational, inert boundary

The future foundation MUST be read-only and derivational. It MUST NOT:

- mutate S, M, R, E, X, A, or B;
- create, normalize, acquire, or persist evidence;
- inspect evidence content or evaluate evidence quality/freshness;
- query capability, evidence, or runtime registries;
- use fuzzy/semantic matching, LLMs, retrieval, or embeddings;
- create or import a universal comparative-effect taxonomy;
- aggregate or reconcile multiple effects;
- score, rank, prefer, filter, or select paths or sources;
- plan or authorize acquisition or execution;
- certify truth or grant cognitive authority;
- create questions or assign question-worthiness or relevance;
- invoke curiosity, goals, initiative, or conversation;
- modify memory or create learning candidates;
- execute actions;
- claim subjective experience or consciousness.

A future core GREEN implementation MUST NOT depend on `app.*`.

## 10. Evidence-source neutrality

Human, creator, household, document, knowledge, task, briefing, acquired, or
other evidence sources participate only through the canonical E already
preserved by S.

Source identity, accessibility, relationship, provenance, quality, freshness,
availability, or runtime readiness cannot by themselves establish a
comparative effect, preference, truth, selection, or authorization.

`HUMAN SOURCE ≠ PRIVILEGED COMPARATIVE-EFFECT SOURCE`.
