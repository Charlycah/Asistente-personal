# ADR M225.4 — Reserved Console Commands & Input Sanitization

## Status

Accepted.

## Context

The development console renders operational evidence with reserved prefixes such as
`OBS>`. A copied observation line could be submitted at the `Carlos>` prompt and
would then enter the conversational pipeline as ordinary user text. This polluted
short-term context and caused an unnecessary provider call.

## Decision

Introduce a deterministic console-input classifier before the runtime boundary.
Inputs are classified as empty, exit, command, reserved, or conversation.

The prefixes `OBS>`, `ROBY>`, `SYS>`, `TRACE>`, `SYSTEM:`, `ASSISTANT:`, and
`USER:` are reserved case-insensitively after leading/trailing whitespace is
removed. Reserved input is rejected locally with a fixed message and never reaches
inference, the journal, retrieval, tools, or persistence.

Existing `/tool` requests remain conversational inputs so the governed tool route
continues to own their interpretation. Exit commands and existing slash commands
retain their M224.5 behavior.

## Consequences

- Console output cannot be accidentally replayed into the LLM.
- The journal remains free of copied operational traces.
- No provider, network, retrieval, or mutation action is performed for rejected
  input.
- Input classification is independently testable and reusable by future console
  surfaces.
