## 2. Canonical ordinary-turn path

The current productive path is:

`Desktop / UI Adapter`

→ `OfficialConversationGateway.submit()`

→ `EndToEndLocalConversation.converse()`

→ `GovernedConversationPipelineRequest`

→ `GovernedOperationalConversationPipeline.process()`

→ `OfficialRuntimeCapabilityRegistry.intercept()`

→ if no operational interception:

`GovernedRuntimePreparation.prepare()`

→ `EnvironmentInferenceRequestPort.build()`

→ recent conversation context

→ governed Memory enrichment

→ other explicitly admitted cognitive/longitudinal contexts

→ provider execution

→ response assembly

→ `LocalConversationTurn`

→ Desktop / Voice Reader.

This is the canonical path to reconcile. The historical `CognitivePipeline` is not
substituted for it.

## 3. Memory and conversational continuity are already reachable

`EndToEndLocalConversation` supplies bounded recent conversation history through
`GovernedConversationPipelineRequest.recent_context`.

`GovernedRuntimePreparation` enriches the inference request with that context through
the canonical context-continuity runtime.

It also invokes the governed Memory runtime when private-context access is allowed and
transports the admitted memory context into the same inference request.

Classification:

`RECENT_CONVERSATION_CONTEXT: REACHABLE`

`GOVERNED_MEMORY_CONTEXT: REACHABLE / ACCESS_BOUNDED`

Therefore the humanization residual is not permission to create another conversational
memory, relationship memory or context store.

## 4. Unified Experience is reachable, but path-bounded

The runtime factory creates exactly one `UnifiedExperienceLayer` and binds it to the
single `OfficialRuntimeCapabilityRegistry`.

The registry applies the experience layer through `_finalize()` / `_present()` to
operationally intercepted results.

Therefore the previous broad classification that ordinary-turn consumption was wholly
unproven is refined.

Classification:

`UNIFIED_EXPERIENCE_LAYER: PRODUCTIVELY_REACHABLE_ON_INTERCEPTED_RESPONSES`

However, when the registry returns `None`, the operational conversation pipeline
continues to provider inference and response assembly. That provider-response path does
not pass through the registry's `_present()` seam.

Classification:

`UNIFIED_EXPERIENCE_PROVIDER_RESPONSE_REACHABILITY: NOT_DEMONSTRATED`

This is a real path asymmetry, but it is not selected here as the first RED candidate
because the experience layer is a post-result presenter and the deeper missing input
semantics must be reconciled first.

## 7. Exact ordinary inference gap

`EnvironmentInferenceRequestPort.build()` currently builds the base LLM request from:

- the current user text;
- executive working-memory prompt context when available;
- owner/session metadata.

`GovernedRuntimePreparation` subsequently enriches that request with canonical recent
conversation context, Memory and selected governed cognitive/longitudinal evidence.

The current ordinary preparation path does not reference:

- `StablePersonalityEngine` or `StablePersonalityManager`;
- `AdaptivePersonalityAuthority` or `AdaptivePersonalityProfile`;
- `RelationshipMemoryManager`;
- simulated inner state;
- explicit inner continuity;
- governed expressive modulation.

The official gateway only *reads* `relationship_memory` and
`adaptive_personality_profile` opportunistically after the turn for relational-affective
evidence. Repository-wide productive inspection does not demonstrate a producer for
those runtime attributes in the current ordinary composition.

Therefore the first causal seam is:

`ORDINARY_PROVIDER_INFERENCE_CANONICAL_PERSONALITY_EXPRESSION_PROJECTION: MISSING`

This is narrower than a generic humanization integration gap.
